## But du travail

Dans le TP2, les sujets n'existaient qu'en mémoire : fermer l'application les faisait disparaître. 

Dans le TP3, tu vas :
1.	 Sauvegarder les données (i.e. sujets et votes) dans une base de données *SQLite*, grâce à la librairie [SujetBD](https://info.cegepmontpetit.ca/3N5-TP3-Librairie-BD/index.html).
2.	 Valider et effectuer des opérations sur les données à l'aide d'une classe de service.
3.	 Tester les méthodes de la classe de service avec des tests unitaires.
4.	 Ajouter un tiroir de navigation permettant aussi de supprimer tous les sujets et tous les votes.

  <TabItem value="La librairie SujetBD" label="Étape 0 : La librairie SujetBD">

    La librairie [**SujetBD**](https://info.cegepmontpetit.ca/3N5-TP3-Librairie-BD/) fournit :

    - Des classes représentant les sujets et les votes (`Sujet` et `Vote`);
    - Une base de données SQLite `SujetVoteDataBase` construite avec [Room](https://developer.android.com/jetpack/androidx/releases/room) et un utilitaire `UtilitaireBD` permettant de l'obtenir;
    - Un DAO (*Data Access Object*), `SujetVoteDAO`, qui fournit les méthodes d’accès direct aux données. Tu n'as pas à écrire de SQL, c'est Room qui s'en charge à partir de ces méthodes d’accès.

    Tu peux consulter la [recette JitPack](../02-recettes/ajout-librairie-jitpack.mdx) pour savoir comment [importer la librairie](https://jitpack.io/#departement-info-cem/3N5-TP3-Librairie-BD). Le [code source de la librairie](https://github.com/departement-info-cem/3N5-TP3-Librairie-BD) est également accessible pour les curieux !

    Pour tester l’accès à la base de données, tu peux exécuter le code suivant dans ton projet :

    ```kotlin
    // Obtient la BD de l'application (LocalContext.current fournit le contexte Android nécessaire)
    val database: SujetVoteDataBase = UtilitaireBD.get(LocalContext.current)

    // Récupère le DAO, l'objet qui donne accès aux méthodes de lecture et d'écriture dans la BD
    val dao: SujetVoteDAO = database.dao()

    // Crée un objet Sujet vide (pas encore enregistré dans la BD)
    val sujet = Sujet()

    // Donne un contenu au sujet
    sujet.contenu = "test"

    // Envoie le sujet à la BD pour l'enregistrer (le DAO ne fait aucune vérification)
    dao.ajouterSujet(sujet)

    // Lit tous les sujets de la BD et les affiche dans le **Logcat**. Appliquez le filtre "system.out" dans le Logcat.
    println(dao.tousLesSujets())
    ```

    Une fois le code exécuté, tu peux inspecter la base de données de ton application à partir d’Android Studio :

    `View -> Tool Windows -> App Inspection -> Database Inspector`

    Développe ensuite la base de données, puis double-clique sur une table, comme `Sujet`, pour en consulter le contenu.

    :::note
    Ce code sert seulement à vérifier le branchement. Retire-le une fois le test fait : dans ton application finale, les écrans n'appellent jamais le DAO directement. Ils passent par le service.
    :::

  <TabItem value="La classe de service" label="Étape 1 : La classe de service (1 point)">

    Le DAO permet d'accéder à la BD en lecture et écriture, mais n'effectue aucune validation sur les entrées de l'utilisateur...
    Pour ce faire, nous utiliserons une classe de service. C'est dans cette classe que vivront les règles de l'application (parfois appelées « logique applicative » ou « règles d'affaires »).

    <Highlight color="tip">1 point</Highlight> Créer une classe de service en remplaçant ``Dupont`` par ton nom, à partir du modèle suivant:

    ```kotlin
    class DupontService(db: SujetVoteDataBase) {

        private val database : SujetVoteDataBase = db
        private val dao : SujetVoteDAO = database.dao()

        fun ajouterSujet(contenu: String) : Long{
            // validation du contenu
            val trimme = contenu.trim()
            if (trimme.length == 0){
                throw TexteVideException()
            }
            if (trimme.length < 5){
                throw TexteCourtException()
            }
            val existant : Optional<Sujet> = dao.sujetParContenu(trimme)
            if (existant.isPresent){
                throw DejaPresentException()
            }
            // Tout va bien, on peut ajouter le sujet dans la BD
            val sujet = Sujet()
            sujet.contenu = trimme
            return dao.ajouterSujet(sujet) // retourne l'id du sujet ajouté
        }

        fun ajouterVote(vote: Vote){
            // TODO à faire plus des tests JUnit
            throw UnsupportedOperationException()
        }

        fun listeSujets(): List<Sujet>{
            throw UnsupportedOperationException()
        }

        fun moyenneVotes(id: Long): Double{
            throw UnsupportedOperationException()
        }

        fun distributionVotes(id: Long): Map<Int, Int>{
            throw UnsupportedOperationException()
        }

        fun supprimerTousLesSujets(){
            throw UnsupportedOperationException()
        }

        fun supprimerTousLesVotes(){
            throw UnsupportedOperationException()
        }

        fun sujetParId(id: Long): Sujet? {
            throw UnsupportedOperationException()
        }
    }
    ```

    Remarquez la structure de `ajouterSujet` : on commence par valider l'entrée de l'utilisateur, et on écrit dans la BD ensuite à l'aide du DAO. Si une règle n'est pas respectée, une [exception](https://info.cegepmontpetit.ca/3M5-Intro-Mobile/cours/10.1-pile-appels-exceptions) est lancée et rien n'est écrit dans la BD. La méthode `ajouterVote` suivra le même principe. La classe de service permet également d'effectuer des opérations sur les données obtenues de la BD. C'est ce que permettront notamment les méthodes `moyenneVotes` et `distributionVotes`. 
    
    Dans l'interface, tu pourras utiliser ton service en créant une instance de celle-ci :

    ```kotlin
    val service : DupontService = DupontService(UtilitaireBD.get(LocalContext.current))
    service.ajouterSujet("Sujet 3")
    ```

    :::note
    L’interface s’occupe **exclusivement** de l’affichage des données ou des messages d’erreurs, pas de la vérification des données. Tu devras modifier l’interface de ton TP2 pour faire appel aux méthodes du service !
    :::

    <TabItem value="Tests du service" label="Étape 2 : Les tests du service">

    Tu devras tester chacune des méthodes de ta classe de service.
    Voici un squelette de la classe de tests:

    ```kotlin
    @RunWith(AndroidJUnit4::class) // tests à placer dans le dossier androidTest
    class TestsService {
        
        private lateinit var service: DupontService

        @Before
        fun setup() {
            val appContext = InstrumentationRegistry.getInstrumentation().targetContext
            val db = UtilitaireBD.getForTests(appContext)
            service = DupontService(db)
        }

        @Test
        fun testAjoutOk() {
            // creer un sujet avec un contenu valide
            service.ajouterSujet("Ceci est un sujet de test")
            // verifier que le sujet a bien été ajouté
            val sujets = service.listeSujets()
            assert(sujets.any { it.contenu == "Ceci est un sujet de test" })
        }

        @Test(expected = TexteVideException::class)
        fun testAjoutSujetVide() {
            // essayer d'ajouter un sujet vide
            service.ajouterSujet("")
        }

        @Test(expected = TexteCourtException::class)
        fun testAjoutSujetTropCourt() {
            // essayer d'ajouter un sujet trop court
            service.ajouterSujet("Test")
        }

        @Test(expected = DejaPresentException::class)
        fun testAjoutSujetExistant() {
            // ajouter un sujet
            service.ajouterSujet("Ceci est un sujet de test")
            // essayer de l'ajouter à nouveau
            service.ajouterSujet("Ceci est un sujet de test")
        }
        
        // TODO compléter les autres tests pour les méthodes restantes
        
    }
    ```

  :::note
    ``testAjoutOk`` utilise ``listeSujets()``. Ce test ne passera qu'après avoir complété cette méthode à l'étape 4.

    ## Étape 3 : Ajout/Création d'un nouveau sujet

    La méthode `ajouterSujet()` ainsi que ses tests sont fournis. Vous devez intégrer la création d'un sujet dans l'interface graphique.

    ## Étape 5 : Ajout d'un vote

    - <Highlight color="info">2 points</Highlight> Au niveau service, vous devez vous assurez qu'il n'y a pas de vote existant pour ce sujet et cette personne.     ## Étape 7 : Tiroir de navigation

    Vous devez implémenter un tiroir de navigation qui contient les options suivantes :

    - <Highlight color="tip">1 point</Highlight> Navigation vers la page d'accueil "Accueil"
    - <Highlight color="tip">1 point</Highlight> Navigation vers la page d'ajout d'un sujet "Ajouter un sujet"
    - <Highlight color="tip">0,5 point</Highlight> Suppression de tous les votes "Suppr. les votes". On doit retourner à la liste des sujets si on y est pas déjà.
    - <Highlight color="tip">0,5 point</Highlight> Suppression de toutes les sujets "Suppr. les sujets". On doit retourner à la liste des sujets si on y est pas déjà.

    Autres éléments à considérer :

    - <Highlight color="tip">1 point</Highlight> Le tiroir de navigation doit être disponible dans toutes les activités.
    - <Highlight color="caution">1 point</Highlight> Vous devez écrire les tests pour vos méthodes de service (suppression sujets et votes).
    - <Highlight color="tip">1 point</Highlight> L'interface doit se mettre à jour. L'ordre est mis à jour si on supprime les votes, la liste à l'écran est vidée si on supprime les sujets.
